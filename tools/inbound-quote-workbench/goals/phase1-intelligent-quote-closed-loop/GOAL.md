# Goal

## Module

`phase1-intelligent-quote-closed-loop`

## Status

`completed_for_user_acceptance` on 2026-07-06. Do not enter Phase 2 before user approval.

## Objective

完成「友易行入境游智能报价经营系统」阶段 1：智能报价闭环上线版。基于现有单页工作台收口，不推倒重写，不做完整 ERP，让 Majfuza 真实客户需求可以从多渠道文本识别一路跑到结构化确认、车型推荐、多城市行程、内部报价、含导游 / 不含导游报价、客户版导出、成交转订单、订单 4 状态、缺成本补录写入产品库记忆和老板基础经营视图。

## Why This Matters

阶段 1 的验收对象是友易行老板和 OP。系统必须先证明真实报价能跑通、产品库能被调用、成本缺失补录后能沉淀为后续可用资源、客户版不泄露内部信息、成交后订单不丢失。只有这条主流程稳定，后续权限、云端协作、老板看板增强、订单履约和供应商治理才有意义。

## Scope

- 多渠道客户需求文本入口，来源包含 WeChat、WhatsApp、Email、OTA、Facebook、官网、手动录入、其他。
- AI / 规则识别后进入结构化需求确认区，由 OP 修改并确认。
- 车型推荐按游客人数、儿童、导游占位、行李缓冲、城市、接送站/机、市内游、长线景区和多城市行程解释。
- 支持昆明、重庆、成都多城市 10 天游程，拆出每日服务项。
- 内部报价表显示成本、售价、毛利、毛利率、缺成本、待审核状态和来源。
- 同一报价单支持 Option A / Option B，例如 With Guide / Without Guide。
- 英文客户版报价单支持 PDF 或长图导出，且隐藏成本、毛利、供应商、内部备注和产品库来源。
- OP 手填成本写入产品库持久记忆；有 Supabase 时写入 `product_resources`，没有云端配置时写入本地 JSON，并标记为 `OP补录待复核`。
- 成交转订单生成最小订单记录，订单状态仅包含：待确认、待安排、进行中、已完成。
- 老板基础视图显示报价、成交、成交金额、利润率、订单状态和待审核产品数量。
- 基础角色显示控制：销售、OP、老板；报告中明确区分前端显示控制和后端真实权限风险。
- 关键识别、确认、报价、导出、转订单过程有轻量审计记录。
- 用 Majfuza 真实客户需求作为主验收案例反复测试并记录证据。

## Out Of Scope

- 完整旅行社 ERP。
- 完整财务应收应付。
- 完整供应商管理系统或供应商评分。
- 多租户 SaaS。
- 自动接入 WeChat、WhatsApp、飞书、企业微信。
- 完整 OP 排班系统和复杂履约。
- 复杂老板 BI。
- 大规模 Next.js / TypeScript 重构。
- 推倒重写 `app.js`。
- 执行数据库结构迁移、删除线上数据或修改生产配置。
- 接入正式登录、后端 RLS 或生产权限闭环，并把它冒充为已完成。

## Redlines

- 不修改 `.env`、`.env.*`、`.env.supabase.local`、`runtime-settings.json` 或任何密钥、token。
- 不执行数据库迁移，不删除云端数据，不改 production 配置。
- 不让 AI 直接决定最终成本价。
- 不把空成本显示为正常 0。
- 不把 OP 补录资源冒充为已老板复核的供应商主数据；必须保留 `OP补录待复核` 或等价状态。
- 不在客户版报价单展示成本、毛利、毛利率、供应商名称、供应商联系方式、内部备注、产品库来源或 OP 操作记录。
- 不删除现有产品库字段。
- 不破坏已有报价主流程和现有通过测试。
- 不擅自进入阶段 2。

## Completion Standard

- Majfuza 案例能完整跑通阶段 1 主链路。
- 现有核心测试通过，并新增或更新必要测试。
- `REPORT.md` 和 `ACCEPTANCE.md` 记录真实测试命令、结果、截图/导出/文件证据路径或明确说明缺口。
- `docs/BUG_LOG.md`、`docs/DEV_LOG.md`、`docs/QA_CHECKLIST.md` 更新到本轮状态，必要时更新 `docs/FEATURE_MAP.md`。
- 明确列出上线试用前仍需用户确认的云端、权限、数据真源和部署风险。

## Rollback

- 本阶段新增模块优先放入独立 `public/js/domain/**` 或小范围前端函数，回滚时删除新增引用和新增文件即可恢复旧主流程。
- 若修改 `app.js`、`index.html`、`styles.css`、`server.js`，只做阶段 1 相关最小补丁，并在 `REPORT.md` 记录回退点。
- 目标文档和验收文档可通过删除 `goals/phase1-intelligent-quote-closed-loop/` 回退。
