# QUOTE_ACCEPTANCE_REPORT

日期：2026-07-05

本文面向客户验收，不写内部实现细节。测试时只判断系统输出是否能被旅行社业务人员使用。

## 验收目标

客户验收只看四件事：

1. 能不能录入客户需求。
2. 能不能生成正确城市和天数的行程。
3. 能不能从产品库取到正确成本。
4. 能不能生成可检查、可交付的报价明细和客户方案。

如果这四件事不稳定，订单、看板、权限都不进入客户验收范围。

## 测试前准备

- 使用本地 Node 服务或带后端 API 的预览环境。
- 不使用纯静态公网页验证 DeepSeek、Supabase、产品库 API。
- 测试前确认 DeepSeek 在线。
- 测试前确认产品库读取的是云端已发布产品资源。
- 如怀疑旧缓存污染，先清空浏览器本地产品库缓存，或点击“重置为系统产品库”。
- 测试时记录浏览器地址、测试时间、输入内容和截图。

## 客户可以怎么测

### 测试 1：基础报价能跑通

操作：

1. 新建报价项目。
2. 输入客户国家、人数、出行日期、服务天数、城市。
3. 填写用车、导游、酒店、门票、餐等服务项。
4. 生成或粘贴行程。
5. 确认线路。
6. 查看报价明细。
7. 查看汇总成本、售价、毛利和缺成本提示。

通过标准：

- 页面不报错。
- 行程天数和客户需求一致。
- 每个报价行有服务类型、城市、来源、供应商、匹配状态。
- 成本不是空白。
- 缺成本显示为待补成本，不显示成正常 0。
- 汇总能正确统计已匹配成本。

失败标准：

- 生成北京默认线，和客户输入城市不一致。
- 行程天数错误。
- 报价明细大量空白。
- 明明产品库有价格，却显示城市不匹配或服务类型不匹配。
- 空成本被显示为正常 0。
- 客户方案显示内部成本、利润或供应商联系方式。

## 建议测试城市 / 行程案例

### 案例 A：重庆 1 到 2 天用车和导游

输入建议：

4 人，抵达重庆机场，需要接机，第二天重庆市内用车，需要英文导游。

通过标准：

- 重庆接机能匹配接送机资源。
- 推荐车型为 7 座或可解释的车型。
- 重庆接机 7 座成本应命中 250。
- 重庆市内一日游 8 小时 7 座成本应命中 700。
- 英文导游能命中导游资源或给出明确待确认原因。
- 无供应商时显示“待绑定供应商”，但不阻断成本。

失败标准：

- 提示“重庆接机服务类型不匹配”。
- 接机成本为空但没有原因。
- 市内用车被识别成接送站。
- 供应商为空导致报价失败。

### 案例 B：重庆武隆包车

输入建议：

4 到 12 人，重庆出发，武隆一日游，需要包车。

通过标准：

- 服务类型识别为包车。
- 重庆武隆包车 14 座到 17 座成本应命中 1500。
- 若车型和人数有多个候选，显示待确认，不算失败。

失败标准：

- 武隆路线完全无法匹配。
- 包车被识别成接送机。
- 多候选直接显示失败。

### 案例 C：北京 2 天

输入建议：

4 人，北京 2 天。第 1 天抵达北京大兴机场，专车接送到酒店。第 2 天游览天安门广场、故宫博物院、景山公园，晚上推荐北京烤鸭。需要舒适型酒店，北京市内用车，英文导游。

通过标准：

- 北京大兴机场接机命中产品库成本。
- 北京市内用车命中产品库成本。
- 英文导游命中导游报价或给出明确待确认原因。
- 故宫门票命中门票资源。
- 同一景点别名不重复生成门票。
- 酒店返回北京同星级候选。
- 餐厅若无成本，显示待补成本，不显示正常 0。

失败标准：

- 北京变成其他城市。
- 大兴机场接机没有来源。
- 故宫门票重复出现“故宫”和“故宫博物院”。
- 餐厅无成本却参与正常成本显示。

### 案例 D：跨城市接送机

输入建议：

成都出发送机，抵达重庆接机，后续重庆本地游。

通过标准：

- 成都送机作为独立用车成本行。
- 重庆接机作为独立用车成本行。
- 后续主行程城市应是重庆，不应继续重复成都阶段。
- 成都送机和重庆接机分别显示城市、服务类型、来源、匹配状态。

失败标准：

- 系统把成都送机重复到后续主行程。
- 重庆接机城市识别成成都。
- 送机、接机合并成一条无法检查的报价行。

## 哪些结果算通过

- 系统输出能让销售或 OP 看懂。
- 成本来自产品库、供应商服务明细或人工录入。
- 每个缺成本项都有原因。
- 有多个候选时显示待确认。
- 客户方案不暴露内部成本。
- DeepSeek 不在线时给出明确错误，而不是假装生成成功。

## 哪些结果算失败

- 报价行没有城市、服务类型、来源或匹配状态。
- 缺成本没有提示。
- 报价明细出现无说明空白行。
- 空成本被当成 0。
- 产品库有真实价格但报价拿不到。
- 供应商未绑定导致成本无法使用。
- 行程城市和客户输入不一致。
- 导出图片或 PDF 点击后无文件、无提示。

## 客户反馈 bug 时必须记录的信息

每个 bug 必须记录：

- 测试时间。
- 测试环境地址。
- 浏览器和网络环境。
- 客户输入原文。
- 结构化字段截图。
- 生成的行程截图。
- 报价明细截图。
- 汇总区截图。
- 产品库中对应资源截图或资源 ID。
- 浏览器控制台报错截图。
- 如果是 API 问题，记录接口地址、状态码和返回内容。
- 是否清过本地缓存。
- 是否使用 DeepSeek。

记录后写入 `docs/BUG_LOG.md`，不要只留在聊天记录里。

## 产品库缺失 vs 报价逻辑 bug

### 属于产品库缺失

- 产品库确实没有该城市资源。
- 产品库有资源但成本为空。
- 产品库只有卖价，没有成本。
- 产品库供应商为待绑定。
- 产品库字段原始 Excel 就为空。
- 餐厅、人均成本、酒店房型等源表缺价格。

处理方式：

- 标记待补成本。
- 记录缺失字段。
- 不把成本填成 0。
- 不把它算作报价逻辑失败。

### 属于报价逻辑 bug

- 产品库有城市、服务类型、车型、路线和成本，但报价匹配失败。
- 接送机、接送站、包车被识别错。
- 城市被跨城市阶段带偏。
- 有多个候选却直接失败。
- 缺供应商导致成本不能进入报价。
- 空成本显示成正常 0。
- 门票别名重复生成多个报价项。
- 报价汇总没有按已匹配成本累加。

处理方式：

- 记录到 `docs/BUG_LOG.md`。
- 保留输入、产品资源、报价行三方证据。
- 下一轮只修一个明确 bug，不混入无关 UI 优化。

## 当前不纳入客户验收的内容

- 正式登录权限。
- 老板创建员工账号。
- 订单履约。
- OP 排团提醒。
- 财务收付款。
- 老板看板。
- 飞书同步。
- 多租户。
- 供应商完整评分。

这些功能可以内部演示方向，但不能承诺为当前交付范围。
