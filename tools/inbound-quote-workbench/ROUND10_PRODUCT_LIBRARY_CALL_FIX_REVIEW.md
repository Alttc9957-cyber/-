# 第十轮产品库调用修复审查报告

审查时间：2026-07-01

审查对象：产品库加载、产品库匹配、确认线路后自动刷新报价主链路。

## 本次修复

1. 产品库本地缓存改为保护式合并。
   - 空的 `youyixing_product_state` 不再覆盖默认产品库。
   - 有效本地产品库会与默认库去重合并，保留导入数据和源码默认数据。

2. 修复报价刷新断路器。
   - `buildQuote()` 中补齐 `vehicleNeeded`，接送机缺价时不再抛 `ReferenceError`。
   - 缺车型 / 缺成本时生成报价行并标记待补成本。

3. 门票匹配链路修正。
   - 真实产品库门票优先。
   - 特色体验未匹配时不再提前截断门票兜底。
   - 天安门等免费景点走“系统兜底 / 免费景点 / 待 OP 确认”。
   - 景山等系统已有参考价但真实产品库未命中的项目走“系统兜底价 / 待 OP 确认真实产品库”。

4. 新增产品库调用自检入口。
   - `window.inboundWorkbench.productCatalogSelfCheck()`
   - 输出产品库数量、报价资源数量、本地缓存状态、北京 7 座包车、北京大兴接机、北京四星酒店、故宫、天安门、景山的调用结果。

- 北京 7 座市区用车：产品库命中，380。

### 4. 接送机缺价异常路径

## 当前边界

1. 天安门、景山如果要成为真实产品库资源，仍需要后续补入产品库表，而不是长期依赖系统兜底。
2. 系统兜底价用于防止主流程空掉，OP 报价前仍应确认真实资源。
3. 本次未改报价架构，也未升级 quoteLegs 多行派单表。
