# 入境旅行社内部工作台原型说明

## 1. 项目背景

这是一个给小规模入境旅行社内部使用的工作台原型，核心使用者包括老板、旅行定制师、旅行操作师、供应商管理人员和财务人员。

当前重点已先落在「报价项目 / 需求报价」工作流，同时补充了「产品资源库」和「供应商管理」模块，用于验证报价、产品、供应商之间如何协同。

## 2. 当前原型运行方式

这是一个静态前端原型。

可直接打开 `index.html` 查看，也可以用本地服务运行：

```bash
node server.js
```

默认访问地址：

```text
http://127.0.0.1:8787
```

## 3. 主要模块

左侧一级模块包括：

- 报价项目
- 订单管理
- 操作排团
- 产品资源库
- 供应商管理
- 财务统计
- 老板看板
- SOP 知识库
- 系统设置

目前功能重点在：

- 报价项目工作台
- 报价项目详情
- 产品资源库
- 供应商管理

## 4. 报价项目工作流

报价项目模块希望解决定制师从询盘到报价、成交、进入操作的完整流程。

当前状态流包括：

- 需求确认中
- 报价中
- 价格已报但未成交
- 已成交待操作
- 已操作待服务
- 已服务待评价

项目详情里包含：

- 客户与项目基本信息
- 日期、人数、城市、特殊需求
- 报价服务项选择
- 行程导入和每日行程维护
- 按服务项填写报价明细
- 汇总检查
- 客人方案输出
- 版本归档

## 5. 需求报价核心逻辑

### 5.1 需求确认

需求确认不再依赖 AI 从聊天记录识别需求，改为定制师手动录入结构化字段。

关键字段包括：

- 项目名称
- 客户账号
- 用户类型
- 用户国家
- 客户来源
- 负责人
- 跟进状态
- 出行日期
- 服务天数
- 成人数
- 儿童数
- 城市
- 特殊要求

### 5.2 报价服务项

报价服务项以「是否包含」为核心开关。

当前服务项包括：

- 用车
- 门票
- 酒店
- 导游
- 大交通
- 用餐
- 其他

其中酒店支持多房型和房间数，房型房间数合计需要等于每天房间数。

### 5.3 行程

行程支持三种方式：

- 按需求生成行程
- 粘贴现成行程后识别并同步
- 沿用历史行程，根据城市和天数推荐匹配方案

当前已优化：

- 单天多行不会被误拆成多天
- 同一城市多天生成内容不会完全重复
- 每日行程天数和需求服务天数不一致时会预警

### 5.4 报价明细

报价不再按一个大表混填，而是按服务项拆分。

每个服务项表格左侧都会显示：

- 日期
- 城市
- 当日行程概览

右侧填写该服务项的成本和卖价。

报价明细会随着行程自动同步，不再需要单独点击「生成报价表」。

### 5.5 门票识别

门票报价会尝试从每日行程中识别景点：

- 优先匹配产品库 / 资源库已有门票
- 如果没有匹配到资源库，也会把疑似景点生成待补价项

### 5.6 汇总检查

系统自动汇总：

- 成本总计
- 卖价总计
- 预计毛利
- 成人均价
- 儿童均价
- 缺失成本项

缺失成本会标明具体日期、城市和服务项。

### 5.7 客人方案

客人方案支持：

- 多语言输出
- 总价 / 人均价 / 分项报价显示控制
- 是否添加水印
- 联系方式配置
- 手动编辑方案
- 导出图片

费用说明会根据报价服务项生成，包含：

- 费用包含明细
- 费用不含 / 备注

酒店会展示参考酒店名；大交通会展示日期、城市段、车次或航班信息。

## 6. 产品资源库

产品资源库以「产品」为主，而不是以供应商为主。

二级品类包括：

- 线路产品
- 用车
- 特色体验
- 景点门票
- 导游
- 酒店
- 餐

产品可以挂接供应商成本，也可以保留手动成本。报价时优先调用产品下有效成本。

## 7. 供应商管理

供应商管理按品类拆分，不同品类有不同字段。

用车供应商字段示例：

- 城市
- 供应商类型
- 供应商名字
- 车型
- 报价
- 营业执照
- 交通许可证
- 银行支付信息

供应商成本会被产品资源库和报价明细调用。

## 8. 希望 GPT 重点分析的问题

请从「旅行行业产品规划师 + 业务流程专家 + SaaS 产品经理」角度分析：

1. 当前工作流是否符合入境旅行社真实报价流程？
2. 需求确认、行程、报价、客人方案之间的数据流是否合理？
3. 报价明细按服务项拆分是否比按天报价更适合定制师？
4. 产品资源库和供应商管理的关系是否设计清楚？
5. 门票识别、历史行程推荐、费用说明生成这些 AI 功能应该如何进一步落地？
6. 当前页面结构、字段、交互是否还有冗余或缺失？
7. 如果要进入真实开发，哪些模块应该优先做成 MVP？
8. 这个系统后续如何与飞书表格、飞书多维表或企业微信/WhatsApp 沟通记录联动？

## 9. 文件说明

- `index.html`：页面结构
- `styles.css`：界面样式
- `app.js`：核心交互逻辑和模拟数据
- `server.js`：本地静态服务
- `assets/`：静态资源
- `screenshots/`：关键页面截图，便于快速看视觉和结构
